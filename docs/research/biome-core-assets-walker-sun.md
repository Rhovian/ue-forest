**1. What to author and what ships**

In paths below, `E=/Users/Shared/Epic Games/UE_5.8/Engine`, `C=E/Plugins/Experimental/PCGBiomeCore/Content`, `S=E/Plugins/Experimental/PCGBiomeSample/Content`. Binary references are existence/string evidence, not an editor inspection of graph connections or evaluated defaults.

- Core supplies Blueprint actors, structures, data-asset templates and native PCG graphs. Both plugins are experimental and disabled by default. Core enables PCG and PCGGeometryScriptInterop; Sample enables Core and PCG. Evidence: `E/Plugins/Experimental/PCGBiomeCore/PCGBiomeCore.uplugin:13–33`; `E/Plugins/Experimental/PCGBiomeSample/PCGBiomeSample.uplugin:13–25`; [overview](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-pcg-biome-core-and-sample-plugins-overview-guide-in-unreal-engine).
- Author the forest definition (name/color/priority), generator assets (type/priority/PCG graph), weighted asset entries and spatial placement. Reusable separate data assets remain supported; since 5.6 definitions/assets can instead live directly on each biome actor. Use separate project assets for reuse across islands. `BP_PCGBiomeCore` bounds global coverage; volumes/splines/textures identify local biomes. Root asset entries require a generator and visual reference; entries sharing a generator share its point set. [Quick start](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-pcg-biome-core-and-sample-plugins-quick-start-guide-in-unreal-engine).
- A biome is a spatial definition plus an asset list. Local graphs produce points; the global graph combines them, resolves priority differences, then spawns meshes, assemblies or actors. An assembly is exported point data from meshes/instances in a level. Runtime detail generation is a separate GPU graph/component around the camera. These are useful mechanisms for logs with moss/seedling children; that nurse-log composition would be project-authored. [Glossary](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-pcg-biome-core-and-sample-plugins-glossary-in-unreal-engine).
- Treat canopy, saplings, deadwood, rocks and understory as project-chosen generator/asset groups, not required named ecological layers. Core supports biome layering/blending, generator priority/bounds overlaps, recursion, per-entry transforms, component overrides, and GPU detail generation. [Overview](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-pcg-biome-core-and-sample-plugins-overview-guide-in-unreal-engine). `strings C/BiomeAssets/Setup/BiomeAsset.uasset` prints `Weight`, `GeneratorSubType`, `FilterOptions`, `ChildAssets`, collision/shadow/distance-field/WPO/cull options; `strings C/BiomeGenerators/Setup/BiomeGenerator.uasset` prints `GeneratorType`, `GeneratorGraph`, `GeneratorAllowOverlap`, and smaller-number/higher-priority tooltip. Definition struct strings print `BiomeName`, `BiomeColor`, `BiomePriority` with the same priority direction.

**Terrain, masks, exclusions and attributes:** smaller biome/generator priority numbers win; equal generator priorities or AllowOverlap bypass overlap removal. Mesh/assembly bounds participate. Weights select assets, rather than defining sampling density. Filters can use point density/Z and computed or projected attributes. Slope can select generator subtypes; landscape paint weights can assign subtypes to asset entries. Hand-placed heroes do not automatically exclude generation: add exclusion volumes/primitives/closed splines with actor tag `PCG_BiomeExclusion` and component tag `BiomeExclusion`; open paths use component tag `BiomePath`. WaterDistance uses a configured water level and distance to below-level points. No automatic WaterBody query is established by this example. [Reference](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-pcg-biome-core-and-sample-plugins-reference-guide-in-unreal-engine), sections Priority-Based Difference, Exclusions, FilterOptions, Generator Subtypes.

**3. First-person movement and Water swimming**

The None variant provides a controllable first-person character, full-body first-person mesh, simple ramps/platforms, and character/controller/game-mode/camera-manager Blueprints. Survival Horror adds sprint/stamina; Arena Shooter adds guns/enemies/UI/jump pads. [UE 5.8 template docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/first-person-template-in-unreal-engine).

Installed C++ None template binds move/look/jump, with Jump/StopJumping at `UE_5.8/Templates/TP_FirstPerson/Source/TP_FirstPerson/TP_FirstPersonCharacter.cpp:47–61,100–119`; no sprint binding in that function. Horror binds sprint at `.../Variant_Horror/HorrorCharacter.cpp:49–59`, changes MaxWalkSpeed at 65–94, and handles stamina/recovery at 98–141. Thus choose None and author sprint, or reuse Horror mechanics deliberately. Move is actor forward/right, with no supplied vertical swimming input in that method: `TP_FirstPersonCharacter.cpp:100–107`.

**Water bodies do not by themselves provide stock CharacterMovement swimming.** CharacterMovement enters MOVE_Swimming when the new PhysicsVolume has `bWaterVolume` and CanEverSwim succeeds: `E/Source/Runtime/Engine/Private/Components/CharacterMovementComponent.cpp:6764–6791`. Water body is an AActor, not APhysicsVolume: `E/Plugins/Experimental/Water/Source/Runtime/Public/WaterBodyActor.h:46–48`; its overlap handlers find BuoyancyComponent and enter/exit water: `.../Private/WaterBodyActor.cpp:112–127`. Buoyancy applies forces through pontoons: `.../Private/BuoyancyComponent.cpp:219–240,304–326`. It is not an automatic character movement-mode adapter.

Corroborating command: `rg -n 'APhysicsVolume|bWaterVolume|MOVE_Swimming|CharacterMovement' E/Plugins/Experimental/Water/Source` returned only `Public/WaterBodyExclusionVolume.h:44` (AWaterBodyExclusionVolume derives APhysicsVolume). That is an exclusion object, not proof water bodies generate swimming volumes.

Project integration options (inference from those APIs): add bWaterVolume Physics Volumes matching playable water areas and enable Can Swim, or implement a water-surface-aware movement adapter using WaterBodyComponent queries. Add ascent/descent controls and tune entry/exit/depth handling. Runtime swimming, waves, collision profiles and drowning logic were not tested; the lead must validate in editor.

**4. Time of day, Lumen and VSM**

Epic ships **Sun Position Calculator** with runtime module (`E/Plugins/Runtime/SunPosition/SunPosition.uplugin:5–21`) and Blueprint-callable latitude/longitude/date/time sun calculation (`.../Source/SunPosition/Public/SunPosition.h:46–54`). Installed `Content/SunSky.uasset` and `BP_SunPosition.uasset` exist. SunSky bundles movable directional light, skylight and SkyAtmosphere; Solar Time is a float hour. [SunSky docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/sun-and-sky-actor-in-unreal-engine).

Runtime updates are explicitly supported: set values on BP_SunPosition then call Update Sun, using a movable directional light. A continually advancing gameplay clock is a project-authored timer/tick/controller; no verified turnkey autoplay day/night cycle, moon or weather system is established here. `strings SunPosition/Content/SunSky.uasset` confirms SolarTime and UpdateSun names but does not prove autoplay behavior. [Epic runtime sun-position instructions](https://dev.epicgames.com/documentation/unreal-engine/geographically-accurate-sun-positioning-tool-in-unreal-engine).

**Yes: software Lumen plus movable lights/VSM supports a running cycle without a lighting bake** (synthesis of the above runtime API and renderer documentation). Lumen supplies dynamic GI; precomputed static lighting is removed when Lumen is enabled. Generate Mesh Distance Fields supports software tracing. Sun/global changes can take seconds to propagate through caches; increasing Scene Lighting Update Speed/Final Gather Lighting Update Speed reduces lag at higher GPU cost. [Lumen GI](https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-global-illumination-and-reflections-in-unreal-engine), [technical details](https://dev.epicgames.com/documentation/unreal-engine/lumen-technical-details-in-unreal-engine).

Known costs: rotating/moving a light invalidates all its VSM cached pages; moving/deforming foliage also invalidates overlapping pages. WPO disable distance, tight bounds and moving-light LOD bias can help. Quantizing a slow solar update is a project profiling option, not a free solution. [VSM caching/deformation/moving lights](https://dev.epicgames.com/documentation/unreal-engine/virtual-shadow-maps-in-unreal-engine). Epic's illustrative Lumen GI/reflection cost is ~8 ms at Epic scalability/1080p internal on next-generation consoles, **not a Mac measurement**. Software tracing does not represent WPO deformation in distance fields; foliage must affect distance-field lighting. Skeletal Dynamic Wind foliage versus software-Lumen tracing needs lead-side validation. [Lumen technical details](https://dev.epicgames.com/documentation/unreal-engine/lumen-technical-details-in-unreal-engine).

Remaining uncertainty is chiefly asset licensing/material/export settings, exact Olympic species availability, and performance/runtime integration on this Mac. The report supplies verified public candidates and explicit verification steps rather than certifying uninspected downloads.
