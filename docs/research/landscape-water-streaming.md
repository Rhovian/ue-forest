# dem-sources — research for ue-forest #9

**Answer:** Prioritise **Jasmund DGM1** for the coastal level: freely licensed, verified anonymous GeoTIFF download, genuine beech-covered chalk relief beside the Baltic. **Implementation inference:** a Landscape heightfield cannot reproduce overhanging chalk cliffs; supplement the terrain with authored cliff meshes. Neither land DEM is verified bathymetry. Inspect marine NoData before conversion and author underwater ground separately. [DHM specification p.5](https://dataforsyningen.dk/asset/PDF/produkt_dokumentation/dk_dhm_terraen_v2_1_aug_2016.pdf), [Epic heightfield architecture](https://dev.epicgames.com/documentation/unreal-engine/landscape-technical-guide-in-unreal-engine).

## 3. UE 5.8 heightmap and import facts

Supported: **16-bit grayscale PNG, r16, r8**, plus **RAW with same-basename JSON defining width/height/bit depth**. Prefer one-channel 16-bit PNG. New Landscape: Import from File, select heightmap; tiled inputs are detected and prompt to use the tiled image path. WP import adds **Grid Size and Region Size** controls; existing WP import uses **Subregion** and can target loaded/all regions. [Epic import/export](https://dev.epicgames.com/documentation/unreal-engine/importing-and-exporting-landscape-heightmaps-in-unreal-engine).

| Spacing / XY scale | Overall vertices | Section / component setup | Components | Side length (derived) |
|---|---|---|---|---|
| 1 m / 100 | 1009×1009 | 63 quads/section; 2×2 sections; 126 quads/component | 8×8 = 64 | 1008 m |
| 0.5 m / 50 | 2017×2017 | Same | 16×16 = 256 | 1008 m |

These dimensions/setups are Epic's recommended sizes; side length is `(vertices−1)×spacing`. Exact 1000 m sides require XY scales approximately **99.20635 / 49.60317**, respectively, or accept the 8 m extra extent. Resampling 1 m DEM to 0.5 m adds vertices, not measured terrain detail. [Epic technical guide](https://dev.epicgames.com/documentation/unreal-engine/landscape-technical-guide-in-unreal-engine).

**Z mapping (derived from Epic):** unsigned sample `v` maps to `z_metres = (v−32768)×ZScale/12800 + actor_Z_metres`. Epic's local interval is −256 to 255.992 before Z scaling (cm); ZScale=100 gives approximately ±256 m. For encoding a vertical span R metres, conventional `ZScale = R×100/512`. If mapping min/max exactly to **0/65535**, exact `ZScale = R×12800/65535`, and actor Z = `min + 32768×R/65535`; the conventional formula differs by one quantisation step at the top. Record the min/max and offset; preserve sea level when positioning the Ocean. [Epic technical guide, Z scale](https://dev.epicgames.com/documentation/unreal-engine/landscape-technical-guide-in-unreal-engine).

## 4. macOS conversion (documented recipe; not executed)

Homebrew supports GDAL: **`brew install gdal`**. No installation performed. [Homebrew formula](https://formulae.brew.sh/formula/gdal).

Example: mosaic neighbouring TIFFs first if the crop crosses a tile boundary. For 1009 vertices at exact 1 m spacing, choose vertex centres from `(E0,N0)` to `(E0+1008,N0+1008)`; GDAL raster *outer* bounds must extend half a pixel past these centres. Below is a synthetic coordinate/height example, not asserted elevations of a chosen forest:

```sh
# Run in scratch directory, with source.tif or a mosaic VRT.
gdalwarp -t_srs EPSG:25833 -r bilinear -ot Float32 \
  -te 413499.5 6046999.5 414508.5 6048008.5 \
  -ts 1009 1009 source.tif crop.tif
# Example chosen vertical range: -20 to +180 m; inspect/fix NoData first.
gdal_translate -of PNG -ot UInt16 -b 1 -mask none \
  -scale -20 180 0 65535 -exponent 1 -a_nodata none \
  crop.tif height.png
gdalinfo height.png
```

Expected: one UInt16 band, 1009×1009. For 2017 vertices at 0.5 m, use outer bounds **413499.75 6046999.75 414508.25 6048008.25**, `-ts 2017 2017`, XY=50. Thus both sample the same vertex-centre extent. For a simpler resized approximation, `gdal_translate -outsize 1009 1009 -r bilinear ...` works, but account for pixel centres instead of silently stretching the extent. NoData removal in the command does **not** repair missing elevations; fix holes/sea cells before quantising. `-exponent 1` clips to the chosen range. [GDAL warp](https://gdal.org/en/stable/programs/gdalwarp.html), [translate](https://gdal.org/en/stable/programs/gdal_translate.html), [PNG supports 16-bit](https://gdal.org/en/stable/drivers/raster/png.html).

The example R=200 m uses conventional ZScale **39.0625**, or exact **39.063096**, actor Z **80.001526 m**, Ocean Z **0 m** for original datum sea level. These are mathematical examples, not verified tidal/datum offsets.

## 5. Water in UE 5.8

- **Experimental**, disabled by default. Installed Epic descriptor: `/Users/Shared/Epic Games/UE_5.8/Engine/Plugins/Experimental/Water/Water.uplugin:13` (`EnabledByDefault:false`) and `:15` (`IsExperimentalVersion:true`). Public [5.8 API plugin page](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/PluginIndex/Water) also locates it under Experimental. Do not equate Water's status with PCG's production status.
- **Ocean/Lake/River:** Ocean and Lake use level closed splines; River uses an open spline with varying point height/depth/width/velocity. They can carve terrain through Landscape brushes with **Enable Edit Layers**. Ocean provides a cheap **Far Distance Mesh** to reach the horizon/world edge. For DEM cliffs, recommendation: preserve imported terrain and disable unwanted carving rather than let default ocean island shaping flatten it. [Epic actors](https://dev.epicgames.com/documentation/unreal-engine/water-body-actors-in-unreal-engine).
- **Lumen/VSM:** Lumen supports Single Layer Water reflections, forced to mirror. VSM integration uses water depth prepass; Epic's Fortnite technical article documents `r.Water.SingleLayer.DepthPrepass 1`. Do not assume a manually enabled cvar fixes every Metal path. [Lumen](https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-global-illumination-and-reflections-in-unreal-engine), [VSM/water technical article](https://www.unrealengine.com/tech-blog/virtual-shadow-maps-in-fortnite-battle-royale-chapter-4).
- **Nanite:** default Water uses its own camera-dependent quadtree mesh and Single Layer Water, not automatic Nanite conversion. Nanite Landscape still needs non-Nanite terrain data for water rendering. Historical Custom Water/Nanite override crash UE-189801 affects 5.2.1 and lists target fix 5.3/Cannot Reproduce; it is **not evidence of a current 5.8 bug**. [Meshing](https://dev.epicgames.com/documentation/unreal-engine/water-meshing-system-and-surface-rendering-in-unreal-engine?application_version=5.8), [Nanite Landscape](https://dev.epicgames.com/documentation/unreal-engine/using-nanite-with-landscapes-in-unreal-engine?lang=en-US), [issue](https://issues.unrealengine.com/issue/UE-189801).
- **Mac/Metal:** general 5.8 support: software Lumen M1+, Nanite/VSM M2+ **Beta**, hardware Lumen M2+ **Experimental**. No Water-specific 5.8 Mac certification or guarantee found. A September 2025 **5.6.1 M3 Ultra** forum report says shallow-water simulation worked in PIE but **baking crashed** with unsupported Metal readback format; unresolved for 5.8 in examined evidence. This is a simulation-bake report, not proof Ocean rendering fails. [5.8 Mac requirements](https://dev.epicgames.com/documentation/unreal-engine/macos-development-requirements-for-unreal-engine), [forum report](https://forums.unrealengine.com/t/ue-v-5-6-1-water-simulation-bake-crash-on-macos-15-6-1-metal-apple-m3-ultra-28-core-cpu-60-core-gpu-32-core/2656076).
- **Cost:** no defensible universal milliseconds/FPS or Mac benchmark found. Additional water mesh draws, classification/reflection/composite passes and underwater post-process contribute; tessellation, visible screen area, extent and reflection quality matter. Far mesh is cheaper than detailed horizon tessellation. Profile `stat water` (CPU) and `stat watermesh` (tiles/vertices/draw calls), plus GPU timing on the target Mac with water on/off at identical camera/settings. [Single Layer Water passes](https://dev.epicgames.com/documentation/unreal-engine/single-layer-water-shading-model-in-unreal-engine), [meshing](https://dev.epicgames.com/documentation/unreal-engine/water-meshing-system-and-surface-rendering-in-unreal-engine?application_version=5.8), [debug/scalability](https://dev.epicgames.com/documentation/unreal-engine/water-debugging-and-scalability-options-in-unreal-engine).

## 6. Streaming and PCG — brief setup recommendation

**Landscape:** one edited Landscape is subdivided into streamable **Landscape Proxies** in editor/runtime. Enable WP **Enable Streaming**; many game templates leave it off. Use HLODs for distant terrain, and actual loaded proxies for walkable terrain. Nanite does not replace WP: it streams alongside conventional Landscape data and both remain resident; Landscape HLOD/proxy streaming behaves the same with Nanite. [Landscape overview](https://dev.epicgames.com/documentation/unreal-engine/landscape-overview), [WP](https://dev.epicgames.com/documentation/unreal-engine/world-partition-in-unreal-engine), [Nanite Landscape](https://dev.epicgames.com/documentation/unreal-engine/using-nanite-with-landscapes-in-unreal-engine?lang=en-US).

**Trees/rocks/foliage:** generate persistent PCG outputs in partition cells, assign Data Layers/HLOD layers, then build HLODs. PCG outputs inherit these assignments; HLOD Instancing uses lowest mesh LOD and suits distant tree representations. Painted foliage has a separate default **256 m instance grid**; it need not equal Landscape or PCG grid size. [PCG+WP](https://dev.epicgames.com/documentation/unreal-engine/using-pcg-with-world-partition-in-unreal-engine), [HLOD](https://dev.epicgames.com/documentation/unreal-engine/world-partition---hierarchical-level-of-detail-in-unreal-engine), [foliage/builder](https://dev.epicgames.com/documentation/unreal-engine/world-partition-builder-commandlet-reference).

**Water:** integrates with WP, but do not expect every water actor to unload with terrain cells. Installed 5.8 **Water Zone and Ocean default `bIsSpatiallyLoaded=false`**: `/Users/Shared/Epic Games/UE_5.8/Engine/Plugins/Experimental/Water/Source/Runtime/Private/WaterZoneActor.cpp:133`, `WaterBodyOceanActor.cpp:22`. Zone has a WP actor descriptor (`WaterZoneActor.cpp:553`); WaterBody is HLOD-relevant (`WaterBodyActor.cpp:724`). Epic announced water HLOD/streaming support in 5.1. Rivers/lakes are actor-streaming candidates, while one continuous Ocean/Zone stays available and its visible tile mesh adjusts around the camera. **Correct shoreline/collision/water-info transitions on this project's 5.8 Metal build remain untested**; the lead must verify crossings and distant horizon in PIE/cooked runtime. [Epic water HLOD announcement](https://www.epicgames.com/site/news/unreal-engine-5-1-is-now-available?lang=en), [WP actor loading rules](https://dev.epicgames.com/documentation/unreal-engine/world-partition-in-unreal-engine).

| PCG path | Disk / runtime tradeoff |
|---|---|
| **Editor-generated partitioned (“baked”)** | Save generated partition actors, mesh-instance components/actor outputs, graph/assets and built HLODs in world packages. Runtime pays streaming, component registration, rendering/collision costs; avoid unintended graph regeneration with the appropriate On Demand trigger. Builder generates and **saves** cells; `-IterativeCellLoading` avoids loading the full world during authoring. [Builder](https://dev.epicgames.com/documentation/unreal-engine/world-partition-builder-commandlet-reference), [trigger discussion](https://forums.unrealengine.com/t/pcg-generation-at-runtime-on-already-generated-volumes/2688878) |
| **Runtime hierarchical generation** | Save graph, sources/settings/assets; generated runtime partition actors are **transient**, not a precomputed world-wide instance bake. Pays scheduling, sampling, spawning, cleanup and rendering as sources move; radii per grid keep small detail nearby. Hierarchical and runtime are separate options and are effective together. [Modes](https://dev.epicgames.com/documentation/unreal-engine/using-pcg-generation-modes-in-unreal-engine?lang=en-US); Epic installed `PCG/Source/PCG/Private/Subsystems/PCGSubsystem.cpp:1401` sets RF_Transient for runtime grids; `RuntimeGen/PCGRuntimeGenScheduler.cpp:2353` does so for pooled actors. |

**Maturity:** PCG framework became production ready in 5.7; CPU partitioned/hierarchical/runtime workflows are documented in 5.8. **GPU PCG remains Beta**, and GPU-spawned instances currently do not support persisted HLODs/static baked lighting. [Epic 5.7 announcement](https://www.unrealengine.com/news/unreal-engine-5-7-is-now-available), [GPU caveats](https://dev.epicgames.com/documentation/unreal-engine/using-pcg-with-gpu-processing-in-unreal-engine?lang=en-US).

**Biome Core supports runtime generation:** separate **Biome Core Runtime** component/graph spawns detailed assets around the camera (GPU path). **Biome Core/Sample remain Experimental.** Use saved partitioned trees/major rocks for reliable distant HLODs and walkable collision; consider runtime detail as a separate optional layer. [Biome Runtime](https://dev.epicgames.com/documentation/en-us/unreal-engine/biome-core-runtime), [Biome maturity](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-pcg-biome-core-and-sample-plugins-in-unreal-engine).
